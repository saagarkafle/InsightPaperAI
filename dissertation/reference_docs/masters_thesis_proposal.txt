1. Abstract

This thesis proposes the design, implementation, and evaluation of InsightPaper AI, a Retrieval-Augmented Generation (RAG) system that ingests academic PDFs, creates semantic embeddings, stores them in a vector database, and uses a large language model (LLaMA 3.1 via Groq's OpenAI-compatible API) to generate accurate, source-grounded answers to research questions. The system will include a user-facing Streamlit UI, extraction of figures and captions, and an evaluation suite comparing generated answers to human-annotated gold responses.

2. Background and Motivation

Researchers and students increasingly rely on LLMs for literature review and summarization, but models often hallucinate or provide ungrounded answers. Retrieval-Augmented Generation combines document retrieval with generation to ground responses in source material, improving factuality and traceability. This project will build a full-stack RAG prototype tailored for academic papers and rigorously evaluate its accuracy and usability.

3. Research Questions and Objectives

Primary research question:
- Can a RAG pipeline built around local embeddings and a generative LLM (LLaMA 3.1 via Groq) produce accurate, source-grounded answers to questions about academic papers, and how does it compare to human baselines?

Secondary questions:
- What retrieval strategies (chunk size, overlap, MMR, hierarchical retrieval) best balance relevance and token efficiency?
- How does context compression (summarization or extraction) impact answer quality and API costs?
- What UI/UX patterns most effectively help researchers validate and navigate sources cited by the model?

Objectives:
- Implement an end-to-end pipeline: PDF parsing, chunking, embedding (sentence-transformers), vector search (Pinecone), and LLM-driven answer generation.
- Implement context optimization strategies (deduplication, compression, hierarchical retrieval).
- Build a Streamlit-based interactive UI for querying, inspection, and feedback.
- Design and run an evaluation comparing the system to human-annotated answers on a curated dataset of papers and questions.

4. Methodology

System Implementation:
- PDF processing: Use PyMuPDF (fitz) to extract text, detect figures and captions, and segment papers into coherent chunks.
- Embeddings: Use sentence-transformers (all-MiniLM-L6-v2) locally to produce 384-dim embeddings for chunks.
- Vector DB: Store embeddings in Pinecone (ServerlessSpec) and implement MMR and relevance scoring for retrieval.
- LLM: Invoke LLaMA 3.1 via Groq using the OpenAI-compatible `openai` Python client configured with Groq base_url. Make model choice configurable for evaluation.
- UI: Streamlit app for uploading PDFs, querying, viewing retrieved chunks, and displaying answer with citations.

Optimization Strategies:
- Token budgeting: estimate tokens for context and trim or compress to fit model limits.
- Context compression: experiment with extractive vs. abstractive summarization of retrieved chunks using smaller/lightweight models or LLM calls.
- Hierarchical retrieval: retrieve top-N, cluster/summarize to top-K.
- Caching and batching: cache summaries and LLM responses; reuse client instance and add retry/backoff logic.

Evaluation:
- Dataset: Curate 50–100 academic papers across 2–3 domains (e.g., NLP and Computer Vision). For each paper, craft 5–10 evaluation questions (factual, interpretive, methodological).
- Gold answers: Create human-annotated gold answers and reference spans from the papers.
- Metrics: Accuracy (exact/partial match as appropriate), factuality (human verification of claims), citation precision (percent of model-cited spans that actually support the claim), and latency/cost per query.
- Ablations: Compare retrieval strategies, context compression methods, and model settings.

5. Expected Contributions

- Empirical findings on retrieval and compression strategies for grounded QA over academic text.
- A reproducible evaluation dataset (papers, questions, gold answers) and evaluation scripts.

8. Ethical Considerations

- Ensure copyrighted papers are used only under permitted license for research purposes; respect publisher terms.
- Protect API keys and personal data; never commit secrets to the repository. Rotate any exposed keys (I noticed a GROQ_API_KEY in `.env` — rotate if real).

9. Risks and Mitigations

- Cost: LLM API usage could be costly — mitigate by using smaller models for preprocessing and caching results.
- Data quality: PDF extraction errors — mitigate with robust parsing and manual inspection tools.
- Hallucination: Emphasize grounding via retrieval and design UI to highlight sources.

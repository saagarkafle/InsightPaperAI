Project Title:
InsightPaper AI: A RAG-Based System for Automated Research Paper Analysis Using Fine-Tuned Sentence Transformers, LLaMA 3.1, and Qwen 3.6

Summary of Project (300 words):

This project proposes InsightPaper AI, a web-based application designed to enable researchers, students, and academics to upload scientific research papers as PDFs and interact with them through natural language questions. The proposed system aims to answer user queries based strictly on the content of uploaded papers, mitigating LLM hallucination and ensuring factual reliability through a Retrieval-Augmented Generation (RAG) architecture supporting multi-model selection between Meta's LLaMA 3.1 (8B) and Alibaba Cloud's Qwen 3.6 (27B).

The primary research question is: how effectively can an end-to-end RAG architecture utilising a fine-tuned Sentence-Transformer embedder, Pinecone vector index, and multi-model LLM generation retrieve relevant paper contexts and generate accurate, source-grounded answers for academic research papers? Supporting sub-questions will investigate the impact of domain-specific contrastive fine-tuning on retrieval accuracy, compare token-level F1, semantic similarity, and LLM-as-a-Judge evaluation metrics, and analyze the effectiveness of metadata-filtered retrieval for real-time scientific search.

The proposed methodology involves parsing PDF documents using PyMuPDF to extract text streams, figures, and captions, and dividing text into 500-word overlapping chunks. Chunks will be embedded into 384-dimensional vector representations using all-MiniLM-L6-v2, which will be fine-tuned on the Kaggle Summarized Research Papers dataset (150 papers, 80/20 train/evaluation split) using MultipleNegativesRankingLoss. Embeddings will be indexed and searched in Pinecone. Retrieved contexts will be injected into prompts sent via Groq to the selected LLM (Qwen 3.6 27B or LLaMA 3.1 8B) under strict source-grounding system prompts.

Key deliverables will be: (1) a functional Streamlit web application with PDF upload, semantic search, AI model selection, summarisation, and QA features; (2) a fine-tuned embedding model; and (3) an empirical evaluation framework measuring Recall@K, Mean Reciprocal Rank (MRR), token-level F1, semantic similarity, and LLM-as-a-Judge quality ratings.

The evaluation plan will compare the baseline embedder against the fine-tuned model on 30 held-out test papers. If post-fine-tuning Recall@K and MRR show measurable improvements over the baseline, it will confirm the efficacy of contrastive domain adaptation. Furthermore, generative QA will be evaluated across Qwen 3.6 27B and LLaMA 3.1 8B; if Qwen 3.6 achieves higher LLM-as-a-Judge ratings for explanation depth while LLaMA 3.1 yields lower latency, it will demonstrate a clear trade-off between parametric scale and real-time response speed.

3. LITERATURE REVIEW
================================================================================

Literature Review: Automated Research Paper Summarisation, Retrieval-Augmented Generation (RAG), and Question Answering

1. Introduction
The volume of scientific literature published globally is expanding at an exponential rate. Researchers, academics, and students across virtually all technical disciplines face an overwhelming corpus of academic papers, preprints, and conference proceedings that cannot feasibly be read in full. Traditional manual reading methods struggle to keep pace with this influx, creating significant cognitive overload, information processing bottlenecks, and lost productivity during literature reviews.

To address this challenge, contemporary Natural Language Processing (NLP) techniques provide automated methods for parsing, indexing, summarising, and extracting knowledge from academic literature. Recent advancements in deep learning, specifically transformer-based architectures, dense vector representation learning, and Large Language Models (LLMs), have transformed document processing and information retrieval. This literature review examines the theoretical foundations, algorithmic components, fine-tuning methodologies, and evaluation frameworks necessary to build an end-to-end system capable of parsing scientific PDFs, performing dense semantic search, and answering natural language questions grounded strictly in paper context.

In the following sections, the core theoretical foundations of transformer-based embeddings, Retrieval-Augmented Generation (RAG), fine-tuning via contrastive learning, vector space index management, and quantitative evaluation metrics are critically reviewed to establish the scientific foundation for this research project.

2. Deep Learning and Document Processing Foundations
2.1. Transformer Architectures in Academic NLP
Modern natural language processing relies predominantly on the Transformer architecture introduced by Vaswani et al. (2017). By replacing traditional recurrent neural networks (RNNs) with multi-head self-attention mechanisms, transformers capture long-range contextual dependencies across sequence tokens in parallel. This architectural leap enabled pre-trained language models to achieve state-of-the-art performance across document parsing, translation, summarisation, and reading comprehension.

In scientific literature processing, applying transformers serves two main goals: (1) mapping dense academic prose into continuous vector representations that capture deep semantic relationships, and (2) generating fluent, contextually accurate answers to user queries grounded strictly within retrieved paper context.

2.2. PDF Parsing, Document Structuring, and Text Chunking
Scientific publications present unique structural challenges compared to raw unstructured text. Research papers contain complex hierarchical elements including multi-column layouts, figures, mathematical equations, captions, and reference sections. Effective document ingestion requires robust extraction tools (such as PyMuPDF/fitz) to separate text streams, extract embedded images, and associate figures with corresponding caption text.

Furthermore, Large Language Models and embedding models operate under strict maximum token context windows. A complete research paper typically contains 5,000 to 20,000 words, far exceeding standard embedding model context limits (e.g., 512 tokens for MiniLM). Direct truncation risks dropping critical methodology or conclusion sections. To resolve this, text chunking protocols divide documents into smaller overlapping segments (e.g., 500 words per chunk with a 100-word sliding window overlap). The sliding window overlap preserves semantic continuity across chunk boundaries, ensuring that key conceptual transitions and multi-sentence statements are not fractured during indexing.

3. Retrieval-Augmented Generation (RAG) and Semantic Search
3.1. Dense Vector Embeddings and Sentence Transformers
Traditional keyword matching algorithms (such as TF-IDF and BM25) rely on literal token matching, failing to capture semantic synonyms, paraphrases, or high-level conceptual context. Dense passage retrieval addresses this limitation by projecting text chunks into continuous low-dimensional vector spaces using Siamese transformer networks.

The Sentence-BERT framework and lightweight MiniLM variants like all-MiniLM-L6-v2 (Reimers & Gurevych, 2019) map sentences into dense 384-dimensional vector spaces. Within this manifold, geometric distances (such as cosine similarity) measure true semantic relevance regardless of surface-level vocabulary differences. For example, a query asking "What methodology was employed?" will map close to chunks describing "experimental setup", "model design", or "algorithmic implementation".

3.2. Embedding Model Fine-Tuning via Contrastive Learning
While general-purpose sentence transformers perform reasonably well on open-domain tasks, domain adaptation and task-specific fine-tuning significantly enhance retrieval precision for research Question Answering.

Fine-tuning embedding models on Reading Comprehension benchmarks such as SQuAD 2.0 (Stanford Question Answering Dataset; Rajpurkar et al., 2018) teaches the model to align natural language questions directly with passage contexts containing the answers. SQuAD 2.0 comprises over 150,000 question-context-answer triples derived from academic and reference articles.

However, general-purpose benchmarks like SQuAD are derived primarily from Wikipedia articles and may not capture the specialised vocabulary, structural conventions, and discourse patterns characteristic of scientific research papers. To address this domain gap, fine-tuning can additionally be performed on curated research paper corpora that contain structured metadata such as paper titles, abstracts, AI-generated summaries, and disciplinary keywords. By constructing training pairs that map research-oriented queries (derived from titles and keywords) to their corresponding abstracts and summaries, the embedding model learns the semantic relationships specific to academic literature.

To fine-tune dense sentence embedder models efficiently without explicit negative labeling, contrastive loss functions such as MultipleNegativesRankingLoss (MNRL) are employed. Given a batch of N (question, positive context) pairs, MNRL treats the positive context of the i-th question as the target, while using the remaining (N - 1) contexts in the mini-batch as implicit negative examples. The model minimizes the cross-entropy loss over softmax-normalized cosine similarity scores:

    Loss = -log( exp(sim(q_i, c_i) / τ) / Σ_j exp(sim(q_i, c_j) / τ) )

This contrastive objective pulls matching question-context pairs closer together in vector space while actively pushing non-matching pairs further apart.

3.3. Cloud Vector Databases and High-Dimensional Indexing
Searching dense vector collections linearly across thousands of chunks exhibits O(N) time complexity, becoming a performance bottleneck as document libraries scale. Vector databases solve this by organizing high-dimensional embeddings into optimized index structures.

Cloud-native vector database platforms like Pinecone manage high-dimensional index management using serverless architectures. By storing 384-dimensional dense vectors alongside rich payload metadata (such as paper_id, chunk_index, source_type, and text snippets), vector databases enable instant cosine similarity retrieval with metadata filtering. This metadata-filtered retrieval allows users to scope semantic searches dynamically to specific research papers, user datasets, or global collections.

3.4. Training and Evaluation Datasets
The selection of appropriate datasets for both model training and system evaluation is fundamental to building a reliable RAG pipeline for scientific literature. Two complementary datasets serve distinct roles in this research.

SQuAD 2.0 (Stanford Question Answering Dataset; Rajpurkar et al., 2018), published on Hugging Face at huggingface.co/datasets/rajpurkar/squad_v2, provides a large-scale general-purpose reading comprehension benchmark. It contains approximately 150,000 question-context-answer triples derived from Wikipedia articles. This dataset is used for initial contrastive fine-tuning of the embedding model, establishing a broad foundation in question-to-passage alignment.

For domain-specific training and evaluation, the Summarized Research Papers dataset (Tyagi, 2024), published on Kaggle at kaggle.com/datasets/tyagi586/summarized-research-papers, provides a curated collection of 150 scientific research paper records spanning multiple disciplines including Medical AI, Computer Vision, Natural Language Processing, and Robotics. Each record contains eight structured fields: Title, Authors, Publication Year, Abstract, AI-Generated Summary, Keywords, Field, and Source Link. The dataset will be split deterministically using an 80/20 ratio (120 papers for training, 30 papers for held-out evaluation), ensuring that evaluation is always performed on unseen papers to prevent data leakage.

3.5. Grounding Answers and Hallucination Mitigation
General-purpose Large Language Models (LLMs) suffer from hallucination, generating plausible-sounding but factual ungrounded statements or invalid citations (Ji et al., 2023). Retrieval-Augmented Generation (P. Lewis et al., 2020; Karpukhin et al., 2020) resolves this by dynamically retrieving the top-K relevant document chunks via vector similarity search before passing them to an instruction-tuned LLM—such as Alibaba Cloud's Qwen 3.6 (27B) or Meta's LLaMA 3.1 (8B)—via high-throughput inference backends like Groq.

By enforcing strict system prompt constraints that compel the LLM to generate answers strictly from the provided context chunks, RAG eliminates hallucination, provides transparent source attribution, and guarantees verifiable answers grounded directly in the target research paper. Furthermore, because RAG dynamically injects the top-K retrieved document passages directly into the LLM's prompt context, the generative model operates strictly as a context-grounded reasoning engine rather than a parametric knowledge base. This architectural decoupling obviates the need for computationally expensive fine-tuning of multi-billion parameter generative models, while guaranteeing factual alignment with the underlying source text.

4. Evaluation Frameworks for RAG and Question Answering Systems
4.1. Automated Question Answering Evaluation Metrics
Evaluating the quality of generated answers in RAG pipelines against gold-standard reference answers requires quantitative, multi-perspective evaluation metrics:
* Exact Match (EM): The percentage of model predictions that match the ground-truth answer string character-for-character after standard text normalization (Rajpurkar et al., 2018).
* Token-Level F1 Score: The harmonic mean of token-level precision and recall between predicted and reference answers. It rewards partial matches and accommodates minor lexical variations:
      Precision = |Predicted ∩ Reference| / |Predicted|
      Recall = |Predicted ∩ Reference| / |Reference|
      F1 = 2 * (Precision * Recall) / (Precision + Recall)
* Semantic Vector Similarity: Measures the cosine similarity between the 384-dimensional dense embeddings of the predicted answer and the reference answer:
      Semantic Similarity = (v_pred · v_ref) / (||v_pred|| * ||v_ref||)
  Unlike F1, semantic similarity captures conceptual alignment even when the model rephrases the answer using entirely different vocabulary (Zhang et al., 2020).
* LLM-as-a-Judge Paradigm: Evaluating generative answer quality across different model scales (such as Qwen 3.6 27B vs LLaMA 3.1 8B) requires evaluating nuanced reasoning and explanation completeness beyond token overlap. The LLM-as-a-Judge framework (Zheng et al., 2023) employs a high-capacity evaluator model to score generated answers on standardized 1–5 scales across three core dimensions: Faithfulness (zero-hallucination grounding), Answer Relevance, and Explanation Completeness.

4.2. Retrieval Quality Metrics
Evaluating retrieval quality independently of LLM generation is critical for diagnosing RAG bottlenecks:
* Recall@K measures the proportion of queries for which at least one relevant document or chunk appears within the top-K retrieved results.
* Mean Reciprocal Rank (MRR) captures not just whether the correct result appears in the top-K, but how highly it is ranked:
      MRR = (1/|Q|) * Σ_i (1 / rank_i)
* Retrieval Margin measures the similarity gap between a query's correct context passage (c_pos) and a top distractor context passage (c_neg):
      Margin = CosineSimilarity(query, c_pos) - CosineSimilarity(query, c_neg)

5. Conclusion and Core Research Questions
The literature confirms that integrating PDF parsing, fine-tuned dense vector embeddings (Sentence-Transformers), cloud vector databases (Pinecone), and instruction-tuned generative LLMs (Qwen 3.6 27B and LLaMA 3.1 8B) under a Retrieval-Augmented Generation architecture offers a scalable solution for scientific literature analysis.

Based on the theoretical gaps and implementation requirements identified in the literature, this research project addresses the following primary research question:
* How effectively can an end-to-end RAG architecture utilizing a fine-tuned Sentence-Transformer embedder, Pinecone vector index, and multi-model LLM generation (Qwen 3.6 27B / LLaMA 3.1 8B) retrieve relevant paper contexts and generate accurate, source-grounded answers for academic research papers?

To answer this overarching question, the following sub-questions guide system design, empirical implementation, and quantitative evaluation:
1. To what extent does fine-tuning a lightweight embedding model (all-MiniLM-L6-v2) on SQuAD 2.0 and the Kaggle Summarized Research Papers dataset via MultipleNegativesRankingLoss improve retrieval recall and mean reciprocal rank compared to the base pre-trained model?
2. How do token-level F1 scores, dense semantic similarity metrics, and LLM-as-a-Judge ratings compare when evaluating Qwen 3.6 27B and LLaMA 3.1 8B model-generated answers against ground-truth dataset answers?
3. How effectively can source-type metadata filtering (PDF vs. Dataset) isolate document domain contexts while maintaining real-time query latency (< 1.5s)?

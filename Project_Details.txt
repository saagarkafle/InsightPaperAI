2. PROJECT DETAILS
================================================================================

Project Title:
InsightPaper AI: A RAG-Based System for Automated Research Paper Analysis Using Fine-Tuned Sentence Transformers and LLaMA 3.1

Summary of Project (300 words):

This project develops InsightPaper AI, a web-based application that enables researchers, students, and academics to upload scientific research papers as PDFs and interact with them through natural language questions. The system answers user queries based strictly on the content of the uploaded paper, eliminating hallucination and ensuring factual accuracy through a Retrieval-Augmented Generation (RAG) architecture.

The primary research question is: how effectively can an end-to-end RAG architecture utilising a fine-tuned Sentence-Transformer embedder, Pinecone vector index, and LLaMA 3.1 LLM retrieve relevant paper contexts and generate accurate, source-grounded answers for academic research papers? Supporting sub-questions investigate the impact of domain-specific fine-tuning on retrieval accuracy, the comparative effectiveness of token-level F1 and semantic similarity evaluation metrics, and the real-time performance of metadata-filtered retrieval.

The methodology combines several techniques. PDF documents are parsed and split into overlapping text chunks using PyMuPDF. Each chunk is embedded into a 384-dimensional vector space using the all-MiniLM-L6-v2 Sentence-Transformer model, which has been fine-tuned on the Kaggle Summarized Research Papers dataset (150 papers, 80/20 train/evaluation split) using MultipleNegativesRankingLoss contrastive learning. Embeddings are stored and searched using Pinecone, a cloud-native vector database. Retrieved context chunks are passed to Meta's LLaMA 3.1 language model via Groq for answer generation, with strict system prompts enforcing source-grounded responses.

The key deliverables are: (1) a fully functional Streamlit web application with PDF upload, semantic search, automated summarisation, and question-answering capabilities; (2) a fine-tuned embedding model demonstrating measurable improvement over the base model; and (3) a quantitative evaluation framework measuring Recall@K, Mean Reciprocal Rank, token-level F1, and semantic similarity.

The project is evaluated by comparing base model retrieval performance (Recall@5: 23.3%, MRR: 11.6%) against the fine-tuned model (Recall@5: 100%, MRR: 100%) on 30 held-out test papers, alongside qualitative user testing of the application interface and answer quality.

4. ANNOTATED CONTENTS LIST FOR THE DISSERTATION
================================================================================

Chapter 1: Introduction
  1.1  Background and Motivation
       — The growing volume of scientific literature and the challenge of
         information overload facing researchers. The need for automated tools.
  1.2  Problem Statement
       — Defines the specific problem: manually reading and extracting knowledge
         from research papers is slow, error-prone, and cannot scale.
  1.3  Aims and Objectives
       — States the project aim (building an end-to-end RAG system) and lists
         specific, measurable objectives for the system and evaluation.
  1.4  Research Questions
       — Presents the primary research question and three supporting sub-questions
         guiding system design and empirical evaluation.
  1.5  Report Structure
       — Brief overview of how the remaining chapters are organised.

Chapter 2: Literature Review
  2.1  Transformer Architectures in Academic NLP
       — Reviews the Transformer architecture (Vaswani et al., 2017) and its
         application to document processing and semantic understanding.
  2.2  PDF Parsing, Document Structuring, and Text Chunking
       — Discusses challenges of scientific PDF extraction and the sliding-window
         chunking strategy used to respect model token limits.
  2.3  Dense Vector Embeddings and Sentence Transformers
       — Reviews Sentence-BERT (Reimers & Gurevych, 2019), the all-MiniLM-L6-v2
         model, and dense passage retrieval as an alternative to keyword matching.
  2.4  Embedding Model Fine-Tuning via Contrastive Learning
       — Examines MultipleNegativesRankingLoss, domain adaptation, and the
         rationale for fine-tuning on research-specific corpora.
  2.5  Training and Evaluation Datasets
       — Reviews SQuAD 2.0 and the Kaggle Summarized Research Papers dataset,
         justifying the selection and 80/20 train/evaluation split strategy.
  2.6  Cloud Vector Databases and High-Dimensional Indexing
       — Reviews Pinecone's serverless architecture, metadata-filtered retrieval,
         and cosine similarity search for high-dimensional vectors.
  2.7  Grounding Answers and Hallucination Mitigation
       — Reviews RAG (Lewis et al., 2020), hallucination in LLMs (Ji et al., 2023),
         and system-prompt-based grounding strategies.
  2.8  Evaluation Frameworks for RAG Systems
       — Reviews Exact Match, F1, semantic similarity, Recall@K, MRR, and
         retrieval margin metrics for assessing system performance.

Chapter 3: System Design and Architecture
  3.1  Overall System Architecture
       — Presents the high-level MVC architecture (Model-View-Controller) and
         the flow from PDF upload through to answer generation.
  3.2  Technology Stack
       — Documents Streamlit, PyMuPDF, Sentence-Transformers, Pinecone, Groq,
         and LLaMA 3.1 with justification for each choice.
  3.3  PDF Parsing Pipeline
       — Details the PyMuPDF-based text extraction, figure detection, caption
         matching, and text cleaning processes.
  3.4  Text Chunking Strategy
       — Explains the 500-word chunk size with 100-word overlap and justifies
         the parameters chosen.
  3.5  Embedding and Indexing Pipeline
       — Details how chunks are embedded, stored in Pinecone with metadata
         (paper_id, chunk_index, source_type), and retrieved.
  3.6  Question Answering Pipeline
       — Describes the full query flow: embedding the question, searching
         Pinecone for top-K chunks, building the LLM prompt, and generating
         the answer with source attribution.
  3.7  Dataset Upload and Evaluation Module
       — Explains the CSV/JSON dataset parser, the evaluation tab, and how
         F1 and semantic similarity scores are computed in-app.
  3.8  Session Management and State Persistence
       — Describes how user sessions are saved and restored automatically.

Chapter 4: Embedding Model Fine-Tuning
  4.1  Base Model Selection
       — Justifies the choice of all-MiniLM-L6-v2 as the base model based on
         its balance of speed, dimensionality, and accuracy.
  4.2  Dataset Preparation
       — Details the Kaggle Summarized Research Papers dataset, the schema
         mapping process, and the deterministic 80/20 train/evaluation split.
  4.3  Training Configuration
       — Documents the MultipleNegativesRankingLoss approach, hyperparameters
         (3 epochs, batch size 16), and the training procedure.
  4.4  Model Evaluation
       — Presents the corpus-wide retrieval benchmark: base model vs fine-tuned
         model on 30 held-out test papers using Recall@5 and MRR.

Chapter 5: Results and Evaluation
  5.1  Retrieval Performance
       — Presents quantitative results: base model Recall@5 (23.3%) and MRR
         (11.6%) vs fine-tuned model Recall@5 (100%) and MRR (100%).
  5.2  Question Answering Quality
       — Reports F1 scores and semantic similarity for generated answers
         evaluated against gold-standard answers from the dataset.
  5.3  System Performance
       — Reports query latency, embedding time, and end-to-end response time.
  5.4  User Interface Evaluation
       — Discusses usability observations from testing the Streamlit interface.
  5.5  Discussion
       — Interprets the results, discusses strengths and limitations of the
         approach, and compares findings with related work.

Chapter 6: Conclusion and Future Work
  6.1  Summary of Contributions
       — Summarises the key achievements: working RAG application, fine-tuned
         embedder with measurable improvement, evaluation framework.
  6.2  Limitations
       — Discusses constraints such as dataset size, single-language support,
         and dependence on external APIs (Groq, Pinecone).
  6.3  Future Work
       — Proposes extensions: multi-paper comparative analysis, citation graph
         integration, larger training corpora, and local LLM deployment.

References
